
# Orbit Virtual Assistant - Master Refactoring & UI/UX Plan

## I. Project Overview & Hardware Context

Orbit is transitioning into a comprehensive, ChatGPT-style AI assistant optimized for local execution. The system runs on a machine with **16GB RAM and an RTX 3060 (6GB VRAM)**, making it capable of running quantized 7B/8B local models alongside lightweight embedding models for RAG.

**Key Refactoring Goals:**

1. **UI/UX Overhaul:** Migrate to a minimalist, side-bar driven interface (ChatGPT style) supporting multiple chat sessions, message management, and dynamic input toggles.
2. **Database Migration:** Transition from fragile JSON file storage to a robust NoSQL/In-memory database (MongoDB or Redis) for efficient chat history and memory management.
3. **Smart Tool Routing:** Unify all external and internal retrievals (including Local RAG) under the `tools/` directory.
4. **Graceful Fallbacks:** Implement primary-fallback LLM logic and natural language fallbacks for unsupported features.

## III. Component Design & Functional Requirements

### 1. Backend Subsystems (`/backend`)

* **API Clients:** `llm_client.py` is the primary router for OpenRouter/Local Models. 
* **Tools (`/tools/`):** `knowledge.py` acts as a standard tool. The Agent dynamically chooses between this (for offline local data) or `web_search.py` (for online queries).
* **Memory (`/core/memory_store.py`):** Must be rewritten to interface with **MongoDB or Redis** to manage multiple chat sessions, pinned messages, and long-term "Assistant Memory", fixing the current JSON empty-array bugs.

### 2. Frontend Subsystems (UI/UX Overhaul)

* **Left Sidebar (Collapsible):**
  * Buttons: New Chat, Recent Chats.
  * Session Settings (Per Chat): Rename (Auto-generated by Agent based on first prompt, but manually editable), Pin/Unpin, Archive/Unarchive (saves to long-term Assistant Memory), Delete.
* **Chat Area (Main View):**
  * Displays text, transcribed voice, timestamps, and images/files (UI prepared for future updates).
  * Message-level settings (Top Right): Pin, Archive, or Delete the current active session.
* **Texting Area (Input Box):**
  * Toggles/Buttons: Add Photos & Files, Create Image, Thinking Mode, Web Search (forces online tools only, blocks local data).
  * Voice Input (Dual Mode):
    * Mode A: Press `Ctrl + M` to record, `ESC` to cancel. Upon completion, audio is transcribed into the Textarea for review (Enter to send, Shift+Enter for new line).
    * Mode B: Hold `Control` to talk, release to instantly send.
* **Feature Fallback Protocol:**
  * If the active LLM lacks a requested feature (e.g., Image Gen, File Upload), the backend must intercept and return a hardcoded response: *"Sorry, I don't have this function. If you want to use this, please use other LLMs that are available for them."*

## IV. Execution Phases (For AI Assistant)

AI Assistant MUST execute these phases one by one upon user request. Do not execute all at once.

* **Phase 1: UI Overhaul (HTML/CSS):** Rewrite `index.html` and `styles.css` to match the Sidebar and Chat Area designs detailed in Section III.
* **Phase 2: Frontend Logic (JS):** Update `app.js` to handle Sidebar toggles, Dual-mode voice input, Textarea shortcuts, and new message rendering.
* **Phase 3: Database Migration:** Design a MongoDB schema for Sessions/Messages and rewrite `memory_store.py`.
* **Phase 4: Tool Routing:** Move `knowledge.py` to `/tools`. Update `orbit_brain.py` and API clients to conditionally use Web Search vs Local RAG based on UI toggles.
* **Phase 5: Graceful Fallbacks:** Add backend logic to intercept unsupported features (Image/File requests) and return the natural language refusal.
